# 口述史工作台 · 阶段性成果与测试数据申请说明

**日期**：2026 年 9 月
**项目**：面向科学技术史研究的口述史数字化工作台（DSH 插件 `dsh-oral-history`）
**代码**：https://github.com/Amoswuuuu/dsh-oral-history

---

## 一、这份材料想说明什么

我们已经做出一个可运行的软件原型，用来处理口述史访谈的完整流程：
**录音建档 → 机器转录 → 逐段人工听校 → 抽取考据卡片 → 构建人物/机构关系图谱**。

在申请真实访谈数据之前，先用**公开的中文语音数据**做了一轮实测，
目的是回答一个具体问题：

> **机器转录到底能省多少人力？哪些地方一定会出错、必须人工介入？**

下面是实测结果。我们不想只给一个"做好了"的结论，而是给出**可复核的数字和具体错例**。

## 三、转录准确率实测（本次的核心数据）

### 测试条件

- **音频**：公开中文语音数据集 AISHELL-1（Apache-2.0 授权）中 30 条录音
- **内容**：新闻播报式朗读语音（房地产政策报道）
- **时长**：每条 3.5–7.6 秒，共约 2.5 分钟
- **模型**：Whisper `base`（1.42 亿参数），本地 CPU 运行，无 GPU
- **硬件**：2 核 Xeon Silver 4110 @ 2.1GHz，6GB 内存
- **评价指标**：字错率（CER）= 编辑距离 ÷ 参考总字数

### 结果

| 指标 | 数值 |
|---|---|
| 样本数 | 30 条 |
| 参考总字数 | 464 字 |
| 编辑距离合计 | 112 字 |
| **字错率 CER** | **24.1%** |
| **字准确率** | **75.9%** |
| 逐条 CER 中位数 | 23.5% |
| 逐条 CER 范围 | 0% – 70% |

**按错误程度分布**：

| 等级 | 条数 | 占比 |
|---|---|---|
| 完全正确 | 2 | 7% |
| 轻微错误（<20%） | 13 | 43% |
| 中等错误（20–40%） | 11 | 37% |
| 严重错误（>40%） | 6 | 20% |

> 上述数字由 `scripts/eval-asr.mjs` 产出，可一键复现：
> `node scripts/eval-asr.mjs --truth <金标准> --hyp <识别结果目录>`

### 速度与资源

| 项目 | 数值 |
|---|---|
| 处理速度 | 82 秒音频耗时 33.8 秒（约 2.4 倍实时） |

## 四、错误类型分析（这部分决定了人工听校的工作量）

我们把错例逐条看过，错误集中在四类，**都不是随机噪声，而是有规律的**：

### 1. 专名与机构名（最危险）

```
真值：同策咨询研究部总监张宏伟认为
机器：同策諮询研究部總监張雄伟认为        ← 人名错（张宏伟→张雄伟），且繁简混杂
```

**人名、机构名一旦错，考据卡片和关系图谱就会建错。** 这类错误无法靠语言模型自行发现，
必须依赖人工听校或预先建立的术语表。

### 2. 同音近音词（口语中最常见）

```
真值：四十一个已正式取消或变相放松了限购
机器：41个以正式取消货变向放松的线构

真值：各地政府便纷纷跟进
机器：各地政府便紛紛更近
```

「变相/变向」「限购/线构」「跟进/更近」——**在访谈口语中这类错误会显著增加**，
因为受访者的发音不如播音员清晰。这正是术语表功能要解决的问题
（实测中登记 4 条术语即修正了 6 处错误）。

### 3. 数字格式不统一

```
真值：截至二零一四年十月份
机器：截止2014年11月份                    ← 格式变了，月份还错了
```

中文数字与阿拉伯数字的转换不统一，且容易连带出错。

### 4. 繁简混用

```
真值：除了北京上海广州深圳四个一线城市和三亚之外
机器：除了北京上海廣州深整四個一線城市和三亞之外
```

Whisper 倾向输出繁体字。**上表中 24.1% 的字错率已经扣除了繁简差异**，
未扣除时为 34.3%。

### 最好的情况

也有完全正确的：

```
真值：为改善居住条件再次申请贷款购买普通商品住房
机器：为改善居住条件再次申请贷款购买普通商品住房    ← 完全一致
```

**结论**：机器转录是一个**有用但不可直接采信的初稿**。
它能完成约 76% 的工作量，剩下约 24% 必须人工介入，且错误集中在最需要准确的地方（专名）。

## 五、为什么需要真实的访谈数据

公开数据集的局限在于**语体不匹配**：

| 维度 | AISHELL-1（公开数据） | 真实口述史访谈 |
|---|---|---|
| 语体 | 朗读新闻稿 | 自然口语、有回忆和停顿 |
| 句长 | 短句，结构完整 | 长句，有冗余和重复 |
| 说话人 | 录音棚环境，发音标准 | 老年人，可能有方言口音 |
| 音质 | 近场高信噪比 | 可能来自老磁带、远场录音 |
| 对话结构 | 单人朗读 | 一问一答，有重叠话轮 |

**因此 75.9% 这个数字不能直接外推到真实口述史**——真实场景大概率会更低。
这正是我们需要真实数据来验证的：**误差到底会扩大到什么程度，
以及术语表机制能挽回多少**。

## 六、测试数据申请说明

### 需要的数据

- **10–20 段访谈录音**，中文，总时长不限
- **配套的精校逐字稿**（作为评估金标准）

### 精校稿的理想格式（按优先级）

1. **带时间戳的分段文本** —— 格式如 `[00:15] 访谈者：……`，可直接导入并验证对齐
2. **纯文本全文** —— 可导入，但无法验证时间轴对齐
3. 最理想是同时附带**说话人标注**（访谈者 / 受访者）

### 我们会用这批数据做什么

1. **实测字错率** —— 拿精校稿作金标准，算出真实的 CER，与本次 75.9% 对比
2. **验证术语表机制的收益** —— 统计登记专名后能挽回多少错误
3. **评估人工听校的实际工作量** —— 量化"每 10 分钟录音需要多少听校时间"
4. **验证时间轴对齐** —— 逐段比对机器分段与精校稿的边界

### 关于数据使用与伦理

- 所有数据仅用于**工具开发测试**，不用于任何公开发布或二次分发
- 音频与逐字稿存储在**本地目录**，不上传任何云服务
- 若数据含敏感内容，我们可只使用**片段**或**脱敏后的文本**
- 如需要，我们可以在测试完成后**彻底删除**数据副本
- 请在授权时明确说明使用范围，我们会严格遵守并写入项目文档

### 可选的额外信息（有助于提升评估质量）

- 录音年代与原始载体（开盘磁带 / 卡带 / 数字）
- 受访者大致年龄段与方言情况
- 访谈者人数与录音环境
